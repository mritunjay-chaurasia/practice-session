1. What is React?
    React is a JavaScript library for building user interfaces. It uses a component-based architecture and a Virtual DOM to efficiently update the UI.
    Benefits:
        Reusable components
        Fast rendering using Virtual DOM
        One-way data flow
        Large ecosystem

2. What is Virtual DOM?
    Virtual DOM is a lightweight copy of the real DOM.
    Working:
        React creates a Virtual DOM.
        When state changes, React creates a new Virtual DOM.
        React compares old and new Virtual DOM (Diffing).
        Only changed elements are updated in the real DOM.

        This improves performance.

3. What is Reconciliation?
    Reconciliation is the process React uses to compare the old Virtual DOM with the new Virtual DOM and update only the changed parts in the actual DOM.

4. What is React Fiber?
    React Fiber is React's reconciliation engine introduced to improve rendering performance.
    Features:
        Incremental rendering
        Prioritization of updates
        Better handling of animations
        Concurrent rendering support

10. Explain useCallback
    useCallback memoizes a function reference;. When a function is passed from a parent component to a child component as a prop, React normally creates a new function reference every time the parent re-renders. Because the function reference changes, the child component may also re-render unnecessarily. useCallback keeps the same function reference between renders unless its dependencies change, helping prevent unnecessary child component re-renders.

    const Child = React.memo(({ onClick }) => {
    console.log("Child Rendered");
    return <button onClick={onClick}>Click</button>;
    });

    function Parent() {
    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {
        console.log("Clicked");
    }, []);

    return (
        <>
        <button onClick={() => setCount(count + 1)}>
            Increment
        </button>

        <Child onClick={handleClick} />
        </>
    );
    }

    Without useCallback
        Parent Render 1 → handleClick = fn1
        Parent Render 2 → handleClick = fn2
        Parent Render 3 → handleClick = fn3
    Since the reference changes every time, React.memo sees a different prop and re-renders the child.

    With useCallback
        Parent Render 1 → handleClick = fn1
        Parent Render 2 → handleClick = fn1
        Parent Render 3 → handleClick = fn1
    The reference stays the same, so React.memo can skip the child re-render.

11. Difference Between useMemo and useCallback

12. What is React.memo?
    React.memo is a Higher-Order Component that Prevents unnecessary re-rendering of functional components.
    Component re-renders only if props change.

    const Child = React.memo(() => {
        console.log("Child Rendered");
        return <h1>Child</h1>;
    });

    function Parent() {
        const [count, setCount] = useState(0);

        return (
            <>
            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>

            <Child />
            </>
        );
    }

    When count changes:
        Parent re-renders ✅
        Child has no props ✅
        React.memo compares previous props {} with current props {}
        They are equal ✅
        Child does not re-render ✅

22- Explain createAsyncThunk and its action lifecycle.
    createAsyncThunk wraps an async function and dispatches three actions automatically: .pending, .fulfilled, .rejected. You handle these in extraReducers to update loading flags, data, and errors.
    export const fetchUser = createAsyncThunk(
    'users/fetchById',
    async (userId, thunkAPI) => {
        const res = await api.getUser(userId);
        return res.data;
    }
    );

    createSlice({
    name: 'users',
    initialState: { data: null, status: 'idle' },
    reducers: {},
    extraReducers: builder => {
        builder
        .addCase(fetchUser.pending,   s => { s.status = 'loading'; })
        .addCase(fetchUser.fulfilled, (s, a) => { s.status = 'succeeded'; s.data = a.payload; })
        .addCase(fetchUser.rejected,  s => { s.status = 'failed'; });
    }
    });

How do you optimize a slow React application?
    First, I identify the bottleneck using React DevTools Profiler and Chrome Performance tools. Then I optimize based on the root cause—prevent unnecessary re-renders with React.memo, useMemo, and useCallback; reduce bundle size using code splitting and lazy loading; optimize API calls with caching and debouncing; virtualize large lists; and improve asset loading. Finally, I re-profile the application to verify the performance improvement.

What causes unnecessary re-renders?
    Unnecessary re-renders are commonly caused by parent component updates, new object or function references, context changes, inline props, unstable keys, and unnecessary global state updates. I use React DevTools Profiler to identify the cause, then optimize with React.memo, useMemo, useCallback, proper state management, and stable references where appropriate.


How do you implement authentication in React?
    I implement authentication using JWT. The React app sends the user's credentials to the backend, which verifies them and issues an access token. In production, I prefer storing sensitive tokens in HTTP-only cookies rather than localStorage for better security. Protected API requests include the access token, and the backend validates it using middleware. On the frontend, I use protected routes to restrict access to authenticated users. I also implement refresh tokens so users remain logged in without repeatedly entering their credentials, while keeping access tokens short-lived for security.

How do you handle API caching?
    I handle API caching using RTK Query or React Query because they provide automatic caching, request deduplication, background refetching, and cache invalidation. I choose cache durations based on how frequently the data changes. After create, update, or delete operations, I invalidate the relevant cache so fresh data is fetched. For search APIs, I use debouncing to reduce unnecessary requests, and for large datasets I use pagination or infinite scrolling. I also rely on browser HTTP caching where appropriate, but I avoid storing sensitive data in local storage

How do you structure a large React project?
    For a large React application, I prefer a feature-based architecture because it scales well as the project grows. Each feature, such as authentication or users, has its own components, pages, hooks, services, and state. Shared UI components like buttons and modals are placed in a common components folder, while API logic is separated into service files. I use Redux Toolkit with RTK Query for global state and server-state management, and keep component-specific UI state local using useState. I also implement lazy loading, code splitting, protected routes, environment-based configuration, and reusable custom hooks. This structure improves maintainability, supports team collaboration, and makes the application easier to extend

    Not accessible via JavaScript.

1. What are the major features introduced in React 19?
Answer

React 19 introduces several improvements to simplify data fetching, forms, and server integration. Some key features are:

    Actions for handling async operations
    useActionState
    useFormStatus
    useOptimistic
    Native support for ref as a prop (no need for forwardRef in many cases)
    Better support for Server Components
    Document Metadata management (<title>, <meta>)
    Improved Suspense and hydration
    Better developer warnings and performance improvements

2. What are Actions in React 19?
    Actions are asynchronous functions used to handle form submissions and state updates. React automatically manages pending, success, and error states.
    
    async function saveUser(formData) {
        await fetch("/api/users", {
            method: "POST",
            body: formData,
        });
    }

    <form action={saveUser}>
        <input name="name" />
        <button type="submit">Save</button>
    </form>

3. What is useActionState?
    useActionState manages state for form actions.

    const [state, formAction, isPending] = useActionState(
    async (prevState, formData) => {
        return await saveUser(formData);
    },
    null
    );

    <form action={formAction}>
        <button disabled={isPending}>
            Save
        </button>
    </form>

4. What is useFormStatus?
    useFormStatus provides the status of the nearest parent form.

    function SubmitButton() {
        const { pending } = useFormStatus();

        return (
            <button disabled={pending}>
            {pending ? "Saving..." : "Save"}
            </button>
        );
    }

    Useful for disabling buttons during submission.

5. What is useOptimistic?
    useOptimistic updates the UI immediately before the server responds, improving perceived performance.

    const [comments, addOptimisticComment] = useOptimistic(
    initialComments,
    (state, newComment) => [...state, newComment]
    );

    Real-world example:
        A user submits a comment:
        Show the comment immediately.
        Send the API request.
        If it fails, remove or update the optimistic comment.

    This provides a smoother user experience.
