7- What is event-loop?
    The Event Loop is a mechanism that continuously checks whether the Call Stack is empty. If it is, the Event Loop takes tasks from the Microtask Queue first and then from the Callback Queue (Macrotask Queue) and pushes them to the Call Stack for execution, enabling JavaScript to perform asynchronous operations while remaining single-threaded.

        JavaScript is single-threaded.
        Call Stack executes synchronous code.
        Promises go to the Microtask Queue.
        setTimeout, setInterval, DOM events go to the Macrotask Queue.
        Microtasks always execute before Macrotasks.
        Event Loop checks if the Call Stack is empty before moving queued tasks to it.

25- Thread pool in nodejs
    Thread pool is a set of worker threads (managed by libuv) that execute blocking operations asynchronously, allowing the event loop to stay responsive.
    Node.js uses a thread pool managed by libuv to execute blocking operations like file system and crypto tasks asynchronously, keeping the event loop non-blocking. The default size is 4 threads.
    How Thread Pool Works (Step-by-Step)
        JS code requests async operation (e.g. fs.readFile)
        Task is sent to libuv thread pool
        Worker thread executes task
        Callback is pushed to event loop
        Event loop executes callback

27- Hoisting in js?
    Hoisting is JavaScript's default behavior where Variable or Function declarations are moved to the top of their scope before code execution.

    Hoisting Works (Conceptually)
    JavaScript engine:
        Allocates memory for variables & functions
        Executes code line by line
Example:-
    a- var (Hoisted + initialized as undefined)
        console.log(a); // undefined
        var a = 10;

        Behind the scenes:
        var a;
        console.log(a);
        a = 10;
    b- let and const 
        console.log(b); // ❌ ReferenceError
        let b = 20;
        Result show : ReferenceError
        Reason: let and const are hoisted but placed in Temporal Dead Zone (TDZ) until initialization.
Hoisting allows variables or functions to be used before they are decleared in the code

28- Currying in js?
Currying in JavaScript is a technique where a function with multiple arguments is transformed into a sequence of functions, each taking one argument at a time.
example===========>
    Instead of:
    f(a, b, c)
    Currying allows:
    f(a)(b)(c)

❌ Normal function==>
    function add(a, b) {
    return a + b;
    }

    add(2, 3); // 5

✅ Curried version
    function add(a) {
        return function (b) {
            return a + b;
        };
    }

    add(2)(3); // 5

Using arrow functions======>
    const add = a => b => a + b;
    add(2)(3);
    
Currying with Multiple Arguments
    const multiply = a => b => c => a * b * c;
    multiply(2)(3)(4); // 24

Why Currying is Useful (Interview Points)
    Function Reusability
        function add(a){
            return function(b){
                return a + b
            }
        }
        const add10 = add(10);

        add10(5); // 15
        add10(20); // 30

51- How js function are used for searching?
    function debounce(fn, delay) {
        let timer;

        return function (...args) {
            clearTimeout(timer);

            timer = setTimeout(() => {
                fn.apply(this, args);
            }, delay);
        };
    }

    const handleSearch = debounce((value) => {
        fetch(`/api/search?q=${value}`);
    }, 500);

    <input onChange={(e) => handleSearch(e.target.value)} />

61- What is builder in Redux?
    builder is used inside extraReducers to handle actions, especially actions created by createAsyncThunk.

    It provides methods like:
        addCase()
        addMatcher()
        addDefaultCase()
        
        const userSlice = createSlice({
        name: "users",
        initialState: {
            data: [],
            loading: false
        },
        reducers: {},
        extraReducers: (builder) => {
            builder
            .addCase(fetchUsers.pending, (state) => {
                state.loading = true;
            })
            .addCase(fetchUsers.fulfilled, (state, action) => {
                state.loading = false;
                state.data = action.payload;
            })
            .addCase(fetchUsers.rejected, (state) => {
                state.loading = false;
            });
        }
        });

71- What is hydration and what's a "hydration mismatch"?
    Hydration is the process where React takes server-rendered HTML and attaches event listeners and state to turn it into a functional SPA on the client.
    Hydration is commonly used in Next.js and other SSR frameworks.

    A hydration mismatch happens when the server-rendered HTML and the client's first render differ — for example, using Date.now() or window.innerWidth during render. React can't reuse the server DOM, logs a warning, and falls back to re-rendering from scratch (losing the SSR benefit).

157- why to useCallback()
    useCallback is used to memoize a function. When a function is passed from a parent component to a child component as a prop, React normally creates a new function reference every time the parent re-renders. Because the function reference changes, the child component may also re-render unnecessarily. useCallback keeps the same function reference between renders unless its dependencies change, helping prevent unnecessary child component re-renders.

    Without useCallback
    Parent Render 1 → handleClick = fn1
    Parent Render 2 → handleClick = fn2
    Parent Render 3 → handleClick = fn3
    Since the reference changes every time, React.memo sees a different prop and re-renders the child.

    With useCallback
    Parent Render 1 → handleClick = fn1
    Parent Render 2 → handleClick = fn1
    Parent Render 3 → handleClick = fn1
    The reference stays the same, so React.memo can skip the child re-render.


    "function reference", they usually mean the memory location (or memory address) of the function object.

    console.log(fn1 === fn2); output => false
