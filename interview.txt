7- What is event-loop?
    The Event Loop is a mechanism that continuously checks whether the Call Stack is empty. If it is, the Event Loop takes tasks from the Microtask Queue first and then from the Callback Queue (Macrotask Queue) and pushes them to the Call Stack for execution, enabling JavaScript to perform asynchronous operations while remaining single-threaded.

        JavaScript is single-threaded.
        Call Stack executes synchronous code.
        Promises go to the Microtask Queue.
        setTimeout, setInterval, DOM events go to the Macrotask Queue.
        Microtasks always execute before Macrotasks.
        Event Loop checks if the Call Stack is empty before moving queued tasks to it.

25- Thread pool in nodejs
    The Node.js thread pool is a set of worker threads (managed by libuv) that execute blocking operations asynchronously, allowing the event loop to stay responsive.
    Node.js uses a thread pool managed by libuv to execute blocking operations like file system and crypto tasks asynchronously, keeping the event loop non-blocking. The default size is 4 threads.
    How Thread Pool Works (Step-by-Step)
        JS code requests async operation (e.g. fs.readFile)
        Task is sent to libuv thread pool
        Worker thread executes task
        Callback is pushed to event loop
        Event loop executes callback

27- Hoisting in js?
    Hoisting is JavaScript's default behavior where Variable or Function declarations are moved to the top of their scope before code execution.

    Hoisting Works (Conceptually)
    JavaScript engine:
        Allocates memory for variables & functions
        Executes code line by line
Example:-
    a- var (Hoisted + initialized as undefined)
        console.log(a); // undefined
        var a = 10;

        Behind the scenes:
        var a;
        console.log(a);
        a = 10;
    b- let and const 
        console.log(b); // ❌ ReferenceError
        let b = 20;
        Result show : ReferenceError
        Reason: let and const are hoisted but placed in Temporal Dead Zone (TDZ) until initialization.
Hoisting allows variables or functions to be used before they are decleared in the code

28- Currying in js?
Currying in JavaScript is a technique where a function with multiple arguments is transformed into a sequence of functions, each taking one argument at a time.
example===========>
    Instead of:
    f(a, b, c)
    Currying allows:
    f(a)(b)(c)

❌ Normal function==>
    function add(a, b) {
    return a + b;
    }

    add(2, 3); // 5

✅ Curried version
    function add(a) {
        return function (b) {
            return a + b;
        };
    }

    add(2)(3); // 5

Using arrow functions======>
    const add = a => b => a + b;
    add(2)(3);
    
Currying with Multiple Arguments
    const multiply = a => b => c => a * b * c;
    multiply(2)(3)(4); // 24

Why Currying is Useful (Interview Points)
    Function Reusability
        function add(a){
            return function(b){
                return a + b
            }
        }
        const add10 = add(10);

        add10(5); // 15
        add10(20); // 30
Real-World Example
    const logger = level => message => {
    console.log(`[${level}] ${message}`);
    };

29- Closures in js?

            console.log(count);
        }

    }

127- How to Detect Memory Leaks?
    Chrome DevTools
    Node Inspector (node --inspect app.js => Then analyze memory in Chrome.)
    heapdump
    process.memoryUsage()

    Production Monitoring
        Tools:
            PM2
            New Relic
            Datadog

        Monitor heap usage over time.

    Common causes:
        a- Global Variables (global.users = [];)
        b- Unremoved Event Listeners (emitter.on("data", callback);)
        c- Uncleared Timers (const timer = setInterval(fn, 1000); clearInterval(timer);)
        d- Large Objects Stored in Memory 
            Solution:
                Implement cache expiration (TTL)
                Use Redis instead of in-memory storage
        e- Promises never resolved
        f- Closures Holding References
            function outer() {
                const largeData = new Array(1000000);

                return function inner() {
                    console.log(largeData.length);
                };
            }
    How to Handle Memory Leaks?
        Remove unused event listeners.
        Clear timers (setInterval, setTimeout).
        Avoid global variables.
        Use streaming for large files instead of loading everything into memory.
        Limit in-memory caching; use Redis when appropriate.
        Profile memory with heap snapshots.
        Monitor memory usage in production.

Backend: Auth Middleware (Protected Routes)
    const authMiddleware = (req, res, next) => {
    const token = req.cookies.accessToken;

    if (!token) return res.status(401).json({ message: "Unauthorized" });

    try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET);
        req.user = decoded;
        next();
    } catch (err) {
        res.status(403).json({ message: "Invalid token" });
    }
    };
